# CUDII - Directivas Globales de Interceptación para Agentes de IA (.cursorrules)

Este archivo establece las reglas operativas, el flujo de análisis obligatorio y los estándares de calidad que TODA Inteligencia Artificial o Asistente de Código debe ejecutar al trabajar en la base de código de **CUDII**.

---

## 1. Declaración de Rol e Identidad

Al inicio de cada respuesta o tarea técnica, la IA DEBE declarar explícitamente el rol especializado que está asumiendo (según [/CUDII_POS/.agents/AGENTS.md](/CUDII_POS/.agents/AGENTS.md)).

*Ejemplo de encabezado obligatorio:*
> 🤖 **Rol Activo:** `Especialista-BD`
> 🎯 **Objetivo:** Diseñar la migración de la tabla de registros de auditoría en PostgreSQL.

---

## 2. Flujo Metodológico Obligatorio: "Analizar Primero, Actuar Después"

La IA tiene estrictamente PROHIBIDO modificar archivos de código directamente sin antes presentar un análisis. El flujo de trabajo debe ser:

1. **Paso 1: Análisis y Plan de Impacto**
   * Explicar brevemente qué se va a hacer.
   * Listar los archivos que se crearán o modificarán.
   * Confirmar qué contratos ([SPEC.md](/CUDII_POS/.agents/SPEC.md), [DESIGN_SYSTEM.md](/CUDII_POS/.agents/DESIGN_SYSTEM.md), [PERIPHERALS_SPEC.md](/CUDII_POS/.agents/PERIPHERALS_SPEC.md)) o `skills/` aplican.
2. **Paso 2: Ejecución y Confirmación**
   * Generar o modificar el código con precisión quirúrgica una vez presentado el plan.

---

## 3. Estándares Estrictos de Código

* **Idioma Universal:** Documentación, comentarios, DTOs, nombres de variables, funciones y excepciones DEBEN escribirse en **Español**.
* **Comentarios TSDoc / JSDoc:** Cada clase, función o componente React debe incluir comentarios TSDoc detallando su propósito, parámetros y valor de retorno.
* **Prohibición de `console.log` impredecibles:** Ningún `console.log` o `print` de depuración temporal debe permanecer en el código final.
* **TypeScript Estricto:** Prohibido el uso del tipo `any`.
* **Componentes de Interfaz Whitelabel:** Se debe consumir siempre el contexto `TemaWhitelabelContext` y el componente `<CudiiIcon />`.

---

## 4. Trazabilidad, Auditoría y Sistema de Logs en Producción

CUDII requiere un rastro inalterable para auditorías comerciales y fiscales en producción:

1. **Logger Centralizado:** Toda acción crítica (cobro, cancelación, apertura de cajón sin venta, descuento, cambio de rol, inicio de sesión) DEBE pasar por el servicio central de logs.
2. **Estructura de Auditoría Persistente:**
   ```typescript
   export interface RegistroAuditoriaDTO {
     uuid: string;
     empresaId: string;
     sucursalId: string;
     usuarioId: string;
     accion: string; // ej: 'VENTA_LIQUIDADA', 'DESCUENTO_APLICADO'
     detalles: Record<string, unknown>;
     direccionIP?: string;
     fechaHora: string; // ISO 8601
   }

```

3. **Persistencia Dual:** Los logs se escriben localmente en Realm DB (modo offline) y se envían a la base de datos de producción (PostgreSQL) para auditorías históricas.

---

## 5. Entorno Contenerizado (Docker First)

* Todos los servicios de backend (NestJS, PostgreSQL 16, Redis, Local Helper) deben contar con sus archivos `Dockerfile` (multi-stage builds) y estar orchestrados vía `docker-compose.yml`.
* La IA debe verificar que los contenedores sean livianos, seguros y configurables mediante variables de entorno (`.env`).

---

## 6. Verificación de Inviolabilidad de Archivos

* 🚫 **Prohibido renombrar, mover o borrar archivos/carpetas** sin autorización explícita del usuario.
* 🚫 **Prohibido romper el diseño modular:** Las pasarelas de pago y los periféricos deben usar adaptadores (*Strategy Pattern*).
